# Design system specification

This directory contains platform design requirements, not components or implementation assets. The normative source is [SPEC-009](../specs/SPEC-009-design-system.md).

## Information design requirements

| Concern | Requirement |
| --- | --- |
| Typography | Use a legible text hierarchy; identifiers and amounts must be distinguishable and copyable. |
| Spacing | Group records by lifecycle relationship; do not visually imply an unauthorized transition. |
| Color | Color may reinforce state but cannot be the sole indication of approval, evidence, or verification. |
| Motion | Motion must preserve temporal order and respect reduced-motion preferences. |
| Iconography | Icons supplement an explicit label; they do not define governance state alone. |
| Components | Name components by domain role, such as `AllocationTimeline` or `EvidenceRecord`, not visual appearance. |
| Diagrams | Use editable Mermaid source and canonical glossary terms. |
| Documentation | Use stable identifiers, tables for ownership, and explicit normative language. |
