# Migration guide: baseline → v1.0.0

## Summary

- **From:** unversioned / repository `main` consumption
- **To:** 1.0.0
- **Impact:** major (first pinable release of the executable canon)
- **Breaking:** n/a (initial baseline)

## Changed artifacts

| ID | Change | Action required |
| --- | --- | --- |
| All SPECs / ADRs | YAML frontmatter metadata required | Consume generated catalog or parse frontmatter |
| CONTRACT-001–007 | Examples and schemas enforceable | Validate produces/consumes against pinned schemas |
| EVENT-001–010 | Schema-valid fenced examples | Align producers to full payloads |
| SPEC-015–019 | Compatibility and trust layer (proposed/accepted as labeled) | Review security and evolution obligations |
| Conformance manifests | New schema under `schemas/meta/` | Adopt example manifests per service |

## Consumer checklist

- [ ] Pin platform package or git tag `v1.0.0` (do not track floating `main` for production).
- [ ] Add a conformance manifest validated against `schemas/meta/conformance-manifest.schema.json`.
- [ ] Validate outbound payloads with Draft 2020-12 schemas from the release package.
- [ ] Replay `demo/community-ai-lab` fixtures.
- [ ] Confirm Approval → Allocation and Evidence → Verification ordering.

## Rollback

Remain on the prior commit pin if not yet on `v1.0.0`. After adopting `v1.0.0`, rollback is a re-pin to the previous tag plus dual-read of any new fields you emitted.
