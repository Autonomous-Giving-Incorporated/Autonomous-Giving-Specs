# Migration guide: v1.x → v2.0.0 donation-tracking money boundary

> Applies to platform release **v2.0.0** (SPEC-023 v2.0.0 and ADR-015).

## Summary

- **From:** 1.x (SPEC-023 v1 Stripe-adjacent donation processing)
- **To:** 2.0.0
- **Impact:** major (required tracking behavior; SPEC-023 incompatible with donation capture)
- **Breaking:** yes for any implementation that charged donations through AGI/Stripe

## Changed artifacts

| ID | Change | Action required |
| --- | --- | --- |
| SPEC-023 | v2.0.0 tracking ledger; no donation capture | Stop donation Checkout/PaymentIntent; ingest connectors only |
| SPEC-024 | v1.2.0 every.org P0; Stripe = tenant billing | Split billing keys from gift webhooks |
| SPEC-026 | New connector adapter rules | Implement verify / persist / `chargeId` / `netAmount` / exceptions / CSV |
| SPEC-027 | New impact loop | Emit ImpactNotice only after Evidence or human waive |
| ADR-015 | Money-boundary decision | Treat as owner lock |
| CONTRACT-006 | v1.1.0 channel `push` | Accept new enum value (backward compatible) |
| CONTRACT-013 / EVENT-011 / SCHEMA-013 | New ImpactNotice | Produce/consume if claiming Impact Relay notify |
| TERM-025–029 | Gift Summary, Pot, Connector, ImpactNotice, Donation Link | Use glossary terms |

## Field-level notes

- Notification `channel` enum **widened** (`push` added). Prior `email` / `webhook` / `in_app` remain valid (MINOR).
- ImpactNotice is a new contract. No existing payload becomes invalid.
- SPEC-023 v1 Stripe donation lifecycle is **withdrawn**. Implementations that still charge donations through AGI are non-conformant.

## Consumer checklist

- [ ] Bump `platform_spec.version` in the conformance manifest to `2.0.0`.
- [ ] Remove AGI donation Checkout / PaymentIntent / refund paths.
- [ ] Persist tenant `donation_link` as an outbound URL.
- [ ] Validate ImpactNotice against `impact-notice.json` before send.
- [ ] Do not send ImpactNotice without connector-supplied contact.
- [ ] Replay Community AI Lab fixtures (unchanged lifecycle sequence).
- [ ] Record migration completion in the implementation repository.

## Rollback

Remain on the prior 1.x pin if donation-tracking SPECs cannot be adopted. After adopting SPEC-023 v2, rollback is a re-pin plus dual-read of any ImpactNotice events already emitted.
